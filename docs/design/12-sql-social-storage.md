## 2. 设计原则

1. **预置表即基线**:7 张表已在基线 schema,新旧库(建库即含)启用零 DDL;一切结构变更走 08 号增量迁移并登记。
2. **成交即时换主,不留账表**:沿用 schema 既有取向——交易/购买不建流水表,一致性由单事务保证;审计依赖现有逐包追踪(tap),不建业务账本。
3. **物理行引用**:上架物品不移主(`private_store_items.item_uid` → `character_items.item_uid` 外键),任何崩溃点物品都在店主名下,不存在「回包」补偿动作。
4. **值域不预设**:rank 档位、手续费、金币上限等全部待协议裁决后落 CHECK/常量;先以宽松约束启用,裁决后按迁移收紧。
5. **裁决前置**:§7 裁决项未闭合前,对应表的写入路径不实现(只读启用或不启用),避免带着错误锚定写数据。

## 3. 分系统存储设计

### 3.1 P0 组队——零持久化

队伍/邀请/副本运行态全内存(`PartyManager` 形态),重启散队;掉落与结算走既有 `character_items`/经验落库路径,无新表无新列。掷点协议已证不存在(P-35),掉落为服务端裁决,落库路径与单人拾取相同。

### 3.2 P2 好友与黑名单

- **好友**:`character_friends` 按现 DDL 启用。**单向关系,添加即生效,无确认流**(CMD 63 单语句写 + 应答);**上下线通知按反向边扇出**——X 上下线时查 `WHERE friend_character_id = X` 的全部边,对在线的 `owner_character_id` 推 NOTI 54/55,该查询正是既有反向索引 `idx_character_friends_friend` 的设计用途;在线状态不入库(presence 由 10 号中枢承担)。
- **黑名单**:J1 已裁决为角色级(现行 DDL 不动);表已启用(2026-10-01,`SqliteStateStore` 社交两表读写)。密语屏蔽校验:客户端拦截通道(NOTI 65 载荷语义)未定,本版「列表可见、不拦截」,拦截留真机后补(登记 11 号 P2)。
- **联动事务**(A12 行为线索,采纳前逐条经 60A1 验证):加黑 → 双向删好友;加好友 → 解除既有拉黑。联动在**单个 IMMEDIATE 事务**内(关系表两写),失败整体回滚。

### 3.3 P3 玩家交易——零新表

- 交换 = **单个 IMMEDIATE 事务**:`UPDATE character_items SET character_id=对方` (k×2 行) + `UPDATE characters.gold` (×2) + 校验(可交易属性、背包容量预检);任一失败整体回滚,两端收失败通知。
- 交易状态机(邀请/报价/确认)全内存,不落库;断线/超时即作废,无恢复语义。
- **交易锁**:60A1 协议面不存在锁族——CMD 名称表全表仅 184 项(ID 0-183),A12 的交易锁 CMD 286-288 **超出表界必不存在**,无需逐点扫描;可交易性校验走 `itemCatalog` 属性判断,若未来在表界内发现锁语义再按 08 纪律补表。

### 3.4 P4 个人商店——启用两表,重启语义精化

- **上架**:`INSERT INTO private_store_items(item_uid, owner_character_id, price_gold, count)`;物品物理行留在店主名下(原则 3)。关摊(未售回包)= 删本表行 + 物品归位标记,单事务。**接线状态(2026-10-01)**:两表未接线——目录暂驻 `PrivateStoreRegistry` 内存态,接线待 85 应答值域与上架通道定案(T9/T10)。
- **购买** = **单个 IMMEDIATE 事务**:`UPDATE character_items SET character_id=买家 WHERE item_uid=? AND character_id=卖家`(所有权条件更新即并发防线)→ `DELETE FROM private_store_items WHERE item_uid=?` → 买家扣款 + 卖家入账(手续费按裁决)→ 容量预检。任一失败整体回滚。
- **重启语义(对 11 号 P4 的精化,消除矛盾)**:schema 既有注释「店名与商品目录需持久化(关店后重开沿用)」与 11 号「重启即清摊、物品随恢复事务回包」冲突。按原则 3,物品本就未移主,**不存在「回包」动作**——精化为:**启动事务 `UPDATE private_stores SET is_open=0 WHERE is_open=1`(强制收摊不开张),上架目录保留**(与「关店重开沿用」一致);玩家重新开摊即在售。11 号 P4 对应表述由本文档取代。
- **CMD 82 轮询**:裁决为社交侧通用轮询(P-35),摊位列表下行走 NOTI 78-85 族;`private_stores` 的读取路径为浏览/区域广播,不与 82 绑定。

### 3.5 P5 工会——启用三表 + 增量列候选

- **建会**(单事务):扣费 → `INSERT INTO guilds` → 会长行 `INSERT INTO guild_members(rank=会长档)`。会名唯一性沿用 `NOCASE UNIQUE`。
- **成员变更**(单事务):邀请接受 = `INSERT guild_members`(+删申请行);退会/开除 = `DELETE`;解散 = `DELETE guilds`(成员行随级联清);**会长转让/被删** = 先 `UPDATE guilds.leader_character_id` 或强制解散(外键不级联的既有约束,应用层强制)。
- **升级**(单事务):扣费 → `UPDATE guilds.level`;**经验挂账**:副本结算事务内 `UPDATE guilds SET ...`(列见 §6 候选,裁决前不写)。
- **公会技能**:A12 有 `guild_skills` 表,本项目基线**未预置**——走 BUY_SKILL(31) 通道的技能若为角色个人持有则零存储(复用现有技能表);若为公会共有(60A1 NOTI 70 信息包含技能位的验证结论决定)则按 08 纪律新增表。**裁决项**。
- `guild_applications`:CMD 78-81 协议未核验(P-35 未覆盖);**保留建表、不写码**,裁决为「60A1 无申请流」则表注释改「预留弃用」。

### 3.6 P6 PVP——零新表

战绩继续写 `characters.pvp_*` 聚合列(既有路径);段位/胜点公式裁决前**只写胜负计数**(经验与段位列维持现值),公式回填后启用。房间/座位/对战运行态全内存(与组队同构)。结算单事务(多行聚合列同事务更新);单进程服务端,不做 A12 式期望值 CAS。

## 4. 事务边界汇总

| 系统 | 事务 | 隔离形态 |
| --- | --- | --- |
| P2 好友/黑名单联动 | 关系表多行写 | IMMEDIATE 单事务 |
| P3 交易交换 | 物品换主 + 双方金币 | IMMEDIATE 单事务,容量预检在前 |
| P4 上架/关摊 | 目录行写 | 单事务 |
| P4 购买 | 所有权条件更新 + 删上架 + 双方金币 | IMMEDIATE 单事务(所有权 WHERE 即并发防线) |
| P5 建会/升降级/挂账 | 金币/费用 + guilds + members | IMMEDIATE 单事务,会长外键约束在应用层前置校验 |
| P6 结算 | characters 聚合列多行更新 | 单事务 |

统一纪律:全部经 `SqliteStateStore` 现有写入管线(08 号形态),不新增并行写入口;WAL 模式不变。

## 5. 黑名单锚定裁决(P2 先导)

| 方案 | 表形态 | 依据 | 代价 |
| --- | --- | --- | --- |
| A. 角色级(现行 DDL) | `character_blacklist(owner,target)` | 表已建;角色粒度与好友对称 | 若客户端语义为账号级,同一账号其他角色被「已拉黑角色」密语时不拦截 |
| B. 账号级改锚 | 新表 `account_blacklist(owner_account_id,target_account_id)`,角色查询 JOIN `characters` | A12 行为线索(账号级);密语按角色发起、屏蔽按账号生效 | 基线表弃用(注释改预留);查询多一跳 JOIN |

**裁决规则**(按序):① IDA 静态——黑名单 case 体/密语校验处屏蔽键取角色还是账号 id;② 静态不可判 → 真机抓包(拉黑后换同账号另一角色密语);③ 均不可得 → 按方案 A 先行并登记 PENDING 复核。改造走 08 增量(新表 + 数据不迁移——原表无数据)。

## 8. 迁移与部署

- **存量库与新库**:7 张表已在基线(`CREATE TABLE IF NOT EXISTS`),启用阶段**零 DDL**;`SqliteDatabaseBootstrap` 行为不变(无库建基线,有库直接用)。

- **单测**(随各阶段 SelfTests):好友增删/级联清理(删角色双向清理);黑名单联动事务回滚;交易交换(成功/买家金币不足/卖家物品变更冲突/背包满)四路径;商店购买(成功/并发购买同一 item_uid 仅一成功/手续费入账);建会/转让/解散的会长外键路径;重启收摊语义(目录保留、is_open 归零)。
