# 60A1 客户端镜头拉近(命中画面放大)逆向

> 适用范围:客户端表现层逆向。本分册记录「镜头拉近效果」——副本内攻击命中(含暴击)时整个画面按倍率放大、并以命中点为中心的表现。
> **结论:纯客户端表现,无协议面**。触发判定、开关读取、状态推进全部在本机客户端内完成;服务端与抓包面不参与该表现,也没有对应 CMD/NOTI case。
> 取证方式:**反编**=Hex-Rays 反编译确认;**反汇**=仅反汇编。本分册结论全部为静态逆向,**未做真机复测**(遗留项见 §7)。
> 地址一律为 VA(ImageBase 0x400000),函数名沿用 IDA 自动名 `sub_XXXXXX`;新增函数已回填 [client-function-register-60cn.md](client-function-register-60cn.md) §9。

## 1. 结论摘要

- **开关**:客户端配置文件 `[DNF COMMON]` 段、键名 `ZOOM EFFECT`,即选项系统下标 3;默认值 1(开启),取值范围 0..1,`0` = 关闭。客户端设置界面中的「开启镜头拉近效果」勾选项即此项(键名与读写通路对应,键名以外的界面文案取自客户端串表,未在本次逆向范围内)。
- **表现**:缩放对象是**整个画面**,不是角色或特效对象;锚点为**命中目标包围盒中心**。
- **主路径参数**:放大倍率 `2.0`、放大时长 `300` ms、保持时长 `1000` ms,之后还原;由命中处理函数在「本机玩家命中目标」时启动。
- **实现形态**:一个"屏幕缩放控制器"对象保存目标倍率/时长/锚点/模式,逐帧推进三段状态机(放大 → 保持 → 还原),把结果写入三个全局量:缩放因子 `n1065353216` @0xB0EF38 与两个方向的屏幕偏移 `n480` / `n640`;渲染侧读取这三个全局量。
- **关闭开关的语义**:不启动新的缩放;若效果正在播放则立即复位(模式 0、缩放 1.0、偏移 0)。
- **参数可配置**:主路径的「倍率 / 放大时长 / 保持时长」三个参数可在客户端补丁(`Client/DFLegacy.Ijl15`)侧改为 Config.ini 可配置,方案见 §9(**草案,待确认后再动代码**)。
- **服务端侧无需实现任何东西**:该表现不在协议面,服务端既不能也无需触发;副本内表现由客户端自己的命中/伤害判定驱动。

## 3. 屏幕缩放控制器

控制器对象由"单位对象 → +0xE4 → 目标对象 → +0xF4"两级取值得到(**反汇**:命中处理中 `mov eax,[esi+0E4h]` / `mov ecx,[eax+0F4h]`,技能路径中同形的 `*(this+57)` / `+244`)。§4 的字段偏移均自该对象起算。

| 偏移 | 类型 | 含义 | 取证 |
|---|---|---|---|
| +0x8D4 | float | 目标缩放倍率 | 反编 |
| +0x8D8 | int | 放大时长(ms) | 反编 |
| +0x8DC | int | 保持时长(ms);`-1` = 不保持,放大结束即还原 | 反编 |
| +0x8E0 | int | 锚点世界 x;`-1` = 取当前视野中心 | 反编 |
| +0x8E4 | int | 锚点世界 y;`-1` = 取当前视野中心 | 反编 |
| +0x8E8 | int | 锚点世界 z(高度);`-1` = 取当前视野中心 | 反编 |
| +0x8EC | u8 | 强制标志:非 0 时无视选项开关 | 反编 |
| +0x8F0 | int | 模式:`0` 空闲 / `1` 放大 / `2` 保持 / `3` 还原 | 反编 |
| +0x8F4 | 结构 | 时间线段对象(§4.3) | 反编 |
| +0x92C | int | 时间线时长样本数(插值上限) | 反编 |

写入侧全局量:

| 全局 | 地址 | 含义 | 取证 |
|---|---|---|---|
| `n1065353216` | 0xB0EF38 | 当前画面缩放因子(float,静止值 1.0) | 反编 |
| `n480` | 见 `sub_4E3550` 写点 | 画面纵向偏移 | 反编 |
| `n640` | 见 `sub_4E6140` 写点 | 画面横向偏移 | 反编 |

锚点取目标包围盒中心:命中路径中按 `原点 + 0.5 × 尺寸` 计算(x = `+0` 字段 + `0.5 × +0x18` 字段,y = `+8` + `0.5 × +0x20`,z = `+0x10` + `0.5 × +0x28`),比例常数 `flt_99F088` @0x99F088 = `0.5`(**反编**)。

## 4. 逐帧推进(`sub_4E6140`)

`sub_4E6140(控制器)` 是唯一的状态推进点(**反编**)。前置条件:模式 `+0x8F0` 非 0,且舞台/视野对象 `+0x50` 非空;不满足直接返回。

### 4.1 锚点换算

1. 若锚点为 `-1`,取视野对象 `*(控制器+0x50)` 的 `vtable+0xD0` 回填的视野中心 `(x, y, z)`,并以 `sub_462D50(1)` / `sub_462DB0(1)` 作为缺省值;否则用 `+0x8E0/+0x8E4/+0x8E8` 存的锚点。
2. 换算为屏幕偏移:

   - 横向偏移 = `锚点x - 320`
   - 纵向偏移 = `锚点y - 锚点z - 120`

   即锚点先减去半个画面(320 / 120),把"世界锚点"变成"相对画面中心的偏移量"。

### 4.2 三段状态机与插值

插值原语 `sub_8F4FE0(起始值, 目标值, 进度, 时长)`(**反编**):`进度 >= 时长` 取目标值;`进度 > 0` 取 `(目标值 - 起始值) * 进度 / 时长 + 起始值`;否则取起始值。整数版本为 `sub_456D30`(偏移量插值用)。

| 模式 | 行为 | 推进 |
|---|---|---|
| 1 放大 | 以 `sub_8F4FE0(1.0, 目标倍率, 进度, 时长)` 插值缩放;对横向、纵向偏移各做一次同形插值(偏移用 `sub_456D30`) | 进度未达时长则继续;达到后若 `+0x8DC` 保持时长非 0,清空时间线、压入保持段,模式转 2;否则转 3 |
| 2 保持 | 直接取 `+0x8D4` 目标倍率,偏移保持 | `sub_431170` 判时间线走完(保持时长非 `-1` 时)后转 3 |
| 3 还原 | 以 `sub_8F4FE0(目标倍率, 1.0, ...)` 反向插值回 1.0,偏移同步回 0 | 时间线走完后调 `sub_4E3550` 复位 |

### 4.3 时间线段对象(`+0x8F4`)

| 相对偏移 | 含义 | 相关函数 |
|---|---|---|
| +0x08 | 起始计时 | `sub_8F3F60` 计算进度时用 |
| +0x10 / +0x18 / +0x20 | 三个通道槽(判空决定时间线是否有效) | `sub_8F3F60` / `sub_8F3E80` |
| +0x30 | 显式经过时间 | `sub_8F3F60` |
| +0x38 | 时长(ms) | `sub_431170` 判完成 |

- `sub_8F3E80(时间线, 时长, 已过时间)`:向时间线压入一段(压段前先由调用方 `sub_405310` 清空);
- `sub_8F3F60(时间线)`:取当前进度(按真实毫秒计,基准来自受保护整数读取);
- `sub_431170(时间线)`:进度 ≥ 时长即完成;
- `sub_405310(时间线)`:清空通道槽;
- `sub_402030`:客户端通用的"受保护整数"读取原语(带校验与篡改回调 `sub_901470`),时间线的进度/时长/通道计数均经该原语读写。

### 4.4 结果写回与钳位

算出缩放与两个偏移后写回全局量 `n1065353216`(缩放)、`::n640` / `::n480`(偏移);偏移按地图像素范围钳位:横向上限 `640`、纵向上限 `480`,下界 `0`(上限按 `sub_464BD0` / `sub_464B00` 取当前地图尺寸)。

### 4.5 复位 `sub_4E3550`

`sub_4E3550(控制器)`(**反编**):模式 `+0x8F0` 置 0、`n1065353216` 置 `1065353216`(float 1.0)、`n640` / `n480` 置 0。

## 5. 触发点(谁启动缩放)

### 5.1 主路径:命中处理(副本内攻击命中)

命中处理函数 `sub_4A97D0` 在 0x4A9937 调用 `sub_4E8AB0`(**反汇/反编**):

```
mov   eax, [esi+0E4h]      ; 单位对象 → 目标对象
test  eax, eax
jz    loc_4A996F
...
mov   ecx, [eax+0F4h]      ; 目标对象 → 屏幕缩放控制器
push  arg_4 / arg_8 / ebx
call  sub_4E8AB0
```

启动条件(全部满足):

1. 攻击者是本机玩家:`攻击者->vtable[0x25C]() == tm_min`(全局本机玩家对象指针 @0xB75A14);
2. `目标->vtable[0x8C]() > 0`。该槽是**转发桩**:0x407480 处为 `mov eax,[ecx]; push 2; call dword ptr [eax+80h]`,即等价于 `目标->vtable[0x80](2) > 0`——带参数 `2` 的取值查询,不是无参取值;
3. `目标->vtable[0x390]() == 4`(语义待确认,见 §7.1);
4. 目标不处于 0x4A983F 处判定的状态(id 529 状态 + `+0x1898` 字段 == 22);
5. 缩放控制器指针非空。

满足后 `sub_4E8AB0`(**反编**)执行:

| 项 | 取值 |
|---|---|
| 目标倍率 `+0x8D4` | `0x40000000` = 2.0 |
| 放大时长 `+0x8D8` | `300` ms |
| 保持时长 `+0x8DC` | `1000` ms |
| 锚点 `+0x8E0/+0x8E4/+0x8E8` | 命中目标包围盒中心 |
| 模式 `+0x8F0` | `1` |

同一函数内还有两个与缩放共用同一触发器的副作用:命中计数器 `+0x170` / `+0x174` 自增,按阈值表 `dword_9A1584` = `{2, 1}` 触发复位;每个计数器各自对应 `+0x200` 起的一个 64 字节时间线槽(与缩放时间线 `+0x8F4` 不是同一对象),循环体内压入 `1500` 段、计数达阈值时清槽后压入 `3000` 段;并按两个计数器的档位选择播放 `R_HK2_1GOOD` / `R_HK2_2GOOD` / `R_HK2_3GOOD`(档位判定:计数 ≥ 20 且另一计数 ≥ 8 取 `1GOOD`,≥ 10 且 ≥ 4 取 `2GOOD`,≥ 2 且 ≥ 2 取 `3GOOD`)。

### 5.2 开关关闭时的分支

`sub_4E8AB0` / `sub_4E5AA0` / `sub_4EA690` 三处均先读 `sub_8A9570(3)`(**反编**,0x4E8C22 / 0x4E5AB6 / 0x4EA6E0):

- 开关开启:正常启动/推进;
- 开关关闭且 `+0x8EC` 强制标志为 0:立即复位 —— 模式 `+0x8F0` = 0、`n1065353216` = 1.0、`dword_B6FEE8` / `dword_B6FEEC` = 0。

即关闭开关不只是"不再启动",还会打断正在播放的缩放。

### 5.3 其它启动点(同一控制器,参数不同)

| 触发来源 | 入口 | 参数 | 取证 |
|---|---|---|---|
| 左轮「暴击致死」被动处理 `sub_5F8FD0`(0x5F914E)→ `sub_4AA510` | `sub_4E5AA0` | 1.5 倍 / 100 ms / 保持 150 ms / 锚点 = 目标包围盒中心 | 反编 |
| HP 变化处理 `sub_4A1E40`(0x4A2051)→ `sub_4E5CC0` | `sub_4E5CC0` | 1.2 倍(`0x3F99999A`)/ 150 ms | 反编 |
| 技能脚本 `sub_5A3530`(0x5A3845,「GPUNCH」族)→ `sub_4E5AA0` | `sub_4E5AA0` | 1.5 倍 | 反编 |
| 热键/宏处理 `sub_494DA0`(0x494F3B)→ `sub_4E5AA0` | `sub_4E5AA0` | 1.5 倍 | 反编 |

各启动点都要求"本机玩家"身份(如 `sub_4AA510` 内 `tm_min == this`),即该表现只在本地玩家自己的攻击上播放。

## 6. 与协议面的关系

### 6.1 静态:全分发 case 扫描(否定结论)

- 开关取自本机配置文件,不来自服务端;
- §5 全部启动点均位于客户端本机逻辑(命中处理、技能脚本、HP 变化、热键处理)的调用链上,不经过 NOTI 分发器 `sub_419420` 或 CMD 应答分发器 `sub_40F290`;
- 触发判定使用本机玩家对象指针 `tm_min`,即"谁在打"由客户端自己判定;
- **全 152 个 NOTI case 逐一扫描**(按跳转表 `0x42A081` 取 case 边界,逐指令匹配三类特征:调用 5 个缩放入口函数、访问控制器字段 `+0x8D4` / `+0x8DC` / `+0x8E0` / `+0x8F0` / `+0x8F4`、引用输出全局 `n1065353216` @0xB0EF38),**命中 0 处**:没有任何 NOTI 分支驱动该缩放。

### 6.2 动态:2026-09-30 抓包对照(DAF-MCP)

当日一次频道会话(7001 频道)的抓包存档中,副本内连续 25 次击杀,每只怪的包序固定为:

| 方向 | 包 | 说明 |
|---|---|---|
| RX | CMD 160 `SDC_DAMAGE_CHECK` | 客户端上行的伤害记录批量上报(发送器 `sub_4AB300`,0x4AB344;内容为「条数 u8 + 逐条(u32 长度 + 记录体)」,记录按 644B 步长遍历) |
| RX | CMD 42 `DIE_MONSTER` | 客户端上行击杀上报(发送器 `sub_843AC0`,0x843B39) |
| TX | NOTI 38 `DIE_MONSTER` | 服务端下行死亡掉落(uniqueId + dropCount + 12B×n 掉落记录 + `{0, 冠军序号, 0}`) |
| RX/TX | CMD 46 `GET_ITEM` / NOTI 39 / NOTI 13 | 拾取与背包刷新 |

对 NOTI 38 的客户端 case(`0x4217CE..0x421EA7`)逐指令核对:该 case 确实操作了一条时间线(0x421D7D `sub_405310` 清空、0x421D9A `sub_8F3E80` 压入 0 段),但对象取自 `[[dword_B5DCE8]+0x54]+0x5C4`,**与缩放控制器(字段 `+0x8D4..`、时间线 `+0x8F4`)不是同一对象**,且该 case 全程未出现 §6.1 的三类缩放特征。故:**日志中的击杀包是缩放发生时刻的伴生记录,不是触发源**。

### 6.3 结论

缩放由客户端自己的命中 / HP 处理启动,服务端不参与:**服务端不应为此下发任何包**;若需要关闭该表现,是客户端侧配置(选项 3)或客户端补丁的事,不在协议面。日志侧的可见相关性只有两条客户端上行记录(伤害上报 CMD 160、击杀上报 CMD 42)——它们与缩放同源(同在本机伤害/命中管线内),但方向为上行,不构成触发。

## 7. 遗留项与待复核

> 本节保留逆向细节;汇总索引见根目录 [PENDING.md](../../PENDING.md)(P-09、P-15～P-17)。

### 7.1 目标判定槽 `vtable[0x390] == 4` 的语义未定

主路径启动条件之一为 `目标->vtable[0x390]() == 4`(0x4A98F8)。全客户端共 20 处以该形态做同类判定(0x482826、0x4B30F7、0x4CD9EA、0x4CFA23、0x4D1551、0x54A18D、0x54A273、0x54CE51、0x58BAB2、0x5BF9D9、0x5E846D、0x5F1C5E、0x61CB2F、0x630BEF、0x6ED4CB、0x6F2293、0x6F2D7F、0x70076B、0x700E9A 等),属**分类值**判定而非逐次命中标志。该槽语义未定,候选读法有二:

1. 命中结果分类(如暴击 / 本次命中致死);
2. 目标对象类别。

已排除的取法:该槽**不是全类统一的"无参分类取值"**——按 RTTI 名逐类读 `vtable+0x390` 可见实现各不相同(如 `CNRDPooledPassiveObject` 一类取到 0x42C9A0 = `test arg,arg; setnl al`,带 1 个参数;另一类取到 0x568540 = `*(this+0x128) = arg`,是写入器),且多个角色/对象类的 vtable 长度不足 0x390(槽值落在相邻数据或字符串上,判为撞车)。命中路径以**无参**方式调用该槽,故目标类必须属于"该槽为无参实现"的类,该类在本次逆向中未定位到。

复核建议(需真机):在副本内攻击怪物,分别以「关闭 / 开启镜头拉近效果」各打一次暴击与一次普通命中,并对比"命中未致死"与"命中致死"两种情形,即可判定该槽属于上述哪种读法。

### 7.2 未定位的调用点

0x5E37CE(`push 1.5f` 后调用 `sub_4E5AA0`)位于函数 `sub_5E3690` 内。该函数形如"按 id 分派 + 按字宽游标读取载荷"(id 常量 `0x47`),但 IDA 未记录任何调用点(仅可能经间接调用或跳转表进入),故其触发来源未确认;若该函数确实由网络侧 id 驱动,则 §6"无协议面"的结论需按此点复核后收窄。

### 7.3 组合计数器与语音名

## 9. 参数可配置方案(IJL15 补丁)【草案·待确认】

> 状态:**草案**,尚未实现(按 D2「文档先行」:文档经确认后再动代码,完成后回写状态并记 CHANGELOG)。
> 目标:让主路径的「倍率 / 放大时长 / 保持时长」三个参数由 `Client/DFLegacy.Ijl15` 的 `Config.ini` 配置,默认值等于客户端原生值(2.0 / 300 ms / 1000 ms),不改写磁盘 PE、只改进程内存。

### 9.1 可行性依据

三个参数在主路径 `sub_4E8AB0` 内由三条「写控制器字段」指令直接给出,均为 4 字节立即数:

| 参数 | 控制器字段 | 写入指令 | 立即数地址 | 原生值 |
|---|---|---|---|---|
| 倍率 | `+0x8D4` | 0x4E8CDA `mov dword ptr [esi+8D4h], imm32` | **0x4E8CE0** | `0x40000000` = 2.0f |
| 放大时长 | `+0x8D8` | 0x4E8CEA `mov dword ptr [esi+8D8h], imm32` | **0x4E8CF0** | `0x0000012C` = 300 |
| 保持时长 | `+0x8DC` | 0x4E8CF4 `mov dword ptr [esi+8DCh], imm32` | **0x4E8CFA** | `0x000003E8` = 1000 |

三条立即数**足够**改变行为,无需动控制流:

- 倍率:模式 1 以 `sub_8F4FE0(1.0, 倍率, 进度, 时长)` 插值到该值(§4.2);
- 放大时长:以 `sub_8F3E80(时间线, +0x8D8, 0)` 压段时间线,时间线长度即插值分母;
- 保持时长:模式 1 走完后以 `+0x8DC` 压保持段,`-1` = 不保持、直接还原(§4.2 模式推进)。

既有补丁框架 `CodePatch{Enabled, Address, Expected[6], Replacement[6]}` 的 6 字节窗口正好容纳:前 4 字节写新立即数,后 2 字节**原样回写后续指令字节**(`Inspect` 按整 6 字节比较,故尾 2 字节必须与现场一致)。

### 9.5 边界与风险

- **版本漂移**:客户端版本不同时 `Expected` 不匹配,既有机制会拒绝整批补丁(不会半途生效),与现有各条补丁同一风险;换客户端后需按 §9.1 重新核对三条立即数。
- **倍率 = 1.0 不等于关闭**:模式 1 还会把画面偏移从当前视野中心插值到命中点(模式 3 再插回),即仍有短暂平移。要彻底关闭请用游戏内选项(选项 3),或另做「启动分支短路」补丁(不在本方案内)。
- **锚点不可配**:命中点与两个方向偏移由寄存器写入(非立即数),本方案不覆盖;若将来需要,走 §9.4 的 hook 路线。
- **连击会把保持时长抬到 ≥1000**:`sub_4E8AB0` 的「已在播」分支里有四处硬编码 `1000`(立即数地址 0x4E8C77 / 0x4E8C7E / 0x4E8CA4 / 0x4E8CB6):模式 1 时「保持时长 ≤ 1000 就抬到 1000」(只增不减),模式 2 时「时间线剩余不足 1000 就清空并重压一段 1000」。因此只改 §9.2 三条立即数时,**`HoldMs < 1000` 在连续命中场景下会被抬回 1000**。要让小保持时长在连击下也生效,需把这四处一并纳入补丁(第 4 组,可选);若不纳入,应在 Config.ini 注释与 README 里写明该限制。
- **开关仍受游戏内选项约束**:补丁只改参数,不绕过选项 3(有意如此:关闭仍由玩家在设置里控制)。
- **范围**:只影响主路径(命中/击杀);技能专用缩放保持原生参数,除非做 §9.4。
- 服务端不参与,无需任何协议改动。

### 9.6 验收标准

1. 原生构建(`patch.bat`)0 警告;CTest `ijl15_compatibility` 通过(含新增默认值断言)。
2. `Config.ini` 缺键或留空 → 行为与原生完全一致(2.0 / 300 / 1000)。
3. `Scale=3.0`、`RampMs=150`、`HoldMs=0` → 副本内命中触发时放大更明显、更快、无保持段。
4. `HoldMs=-1` → 放大结束即还原,无保持。
5. 关掉游戏内选项 3 → 完全不出现缩放(证明补丁未绕过开关)。
6. 客户端字节不符预期时,按既有失败路径提示 `DNF patch bytes do not match` 且不生效。

## 10. 附录:主路径 `sub_4E8AB0` 伪代码

> 形式说明:下表为按 IDA(Hex-Rays)反编译输出整理后的**等价形式**——只把循环体开头四处「受保护整数槽」的 XOR 写折叠成一行注释(原始输出中这些行展开为对 `dword_CFD458+17/+18` 两张加密表的四次读改写),其余语句、分支与调用顺序与原文一致。字段偏移已由 `this + 4*v4 + 368` 这类指针算术还原为字节偏移。
> 取证:**反编**。原始输出见 IDA 数据库(函数 `sub_4E8AB0` @0x4E8AB0,`0x4E8ABC..0x4E8D92`)。

```c
char __thiscall sub_4E8AB0(int this, int a2, char a3, int a4)
//  this = 屏幕缩放控制器(§3)
//  a2   = 命中目标判定结果(0/1),决定循环跑 a2+1 趟
//  a3   = 抑制标志,非 0 时立刻跳出(跳过计数与缩放)
//  a4   = 命中位置来源对象(包围盒 origin + size)
{
    v4 = 0;  v17 = 0;
    v14 = a2 + 1;
    if (a2 + 1 <= 0) goto LABEL_20;          // a2 为负:跳过计数,只做档位语音

    while (1)
    {
        // ① 复位本槽的两个受保护整数槽(加密写:同一地址 XOR 一次即归零)
        //    slot = this + (v4 << 6);索引取自 *(slot + 0x194) 与 *(slot + 0x198)
        sub_8F3E80(1500, 0);                 // 向该槽时间线压 1500 段(ecx 隐式为该槽对象)

        if (a3) break;                       // 抑制标志:到此为止

        // ② 命中计数
        v7 = *(this + 4 * v4 + 0x170) + 1;   // 计数器[v4]:v4=0 → +0x170,v4=1 → +0x174
        *(this + 4 * v4 + 0x170) = v7;
        if (v7 >= dword_9A1584[v4])          // 阈值表 {2, 1}
        {
            *(this + 4 * v4 + 0x1F8) = v7;   // 计数快照
            sub_405310(((v4 + 8) << 6) + this);  // 清空该槽时间线
            sub_8F3E80(3000, 0);             // 压 3000 段
        }

        // ③ 只在 v4 == 1 这一趟处理缩放
        if (v4 == 1)
        {
            // 命中目标包围盒中心 = origin + 0.5 * size(flt_99F088 = 0.5)
            v15 = sub_418260(a4 + 8)  + sub_418260(a4 + 32) * 0.5f;   // y
            v16 = sub_418260(a4 + 0)  + sub_418260(a4 + 24) * 0.5f;   // x
            v21 = sub_418260(a4 + 16) + sub_418260(a4 + 40) * 0.5f;   // z

            if (sub_8A9570(3))               // 选项 3 = ZOOM EFFECT(「镜头拉近效果」)
            {
                n2_1 = *(this + 0x8F0);      // 当前模式
                *(this + 0x8EC) = 0;         // 清强制标志

                if (n2_1)                    // —— 已在播:只做加长 / 续播
                {
                    if (n2_1 == 1)           // 放大中:保持时长抬到 ≥1000(只增不减)
                    {
                        n1000 = *(this + 0x8DC);
                        if (n1000 <= 1000) n1000 = 1000;
                        *(this + 0x8DC) = n1000;
                    }
                    else if (n2_1 == 2 && sub_4D18F0(this + 0x8F4) < 1000)
                    {                        // 保持中:剩余不足 1000 → 重压保持段
                        *(this + 0x8DC) = 1000;
                        sub_405310(this + 0x8F4);
                        sub_8F3E80(*(this + 0x8DC), 0);
                    }
                }
                else                         // —— 空闲:启动一次新的拉近
                {
```
