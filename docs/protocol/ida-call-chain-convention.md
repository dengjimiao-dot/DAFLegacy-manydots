# 逆向调用链记录规范(协议文档强制项)

> 适用范围:`docs/protocol/` 下所有 `packet-detail-*.md` 与后续新功能的逆向文档。
> 范例:[packet-detail-party-60cn.md](packet-detail-party-60cn.md) 附"客户端调用链"章。
> 全项目已恢复的函数统一登记在 [client-function-register-60cn.md](client-function-register-60cn.md),新文档只登记增量并回填登记表。

## 1. 为什么强制

- 封包格式会随客户端版本漂移,只有绑定到具体函数地址的结论才可复核、可迁移(换客户端时逐地址重验即可,不必整篇重推)。
- 调用链记录了"格式是**谁**读的",比格式表本身更防错:同一封包在不同状态下可能走不同 case(如 NOTI 分发器的 default 分支、CMD 应答的状态前置检查)。

## 2. 必须记录的五类条目

每篇封包格式文档的"客户端调用链"章按以下分类列表,列固定为 **函数/数据 | 地址 | 功能**:

1. **分发行**:type/protocol 分发函数、跳转表与 LUT 地址、case 边界(NOTI 分发器 `sub_419420` 跳转表 `0x42A081`;CMD 应答分发器 `sub_40F290` 经 LUT `byte_417638` → 跳转表 `0x417480`)。
2. **读取/写入原语**:全局游标读取器(`sub_8F5120` u8 / `sub_8F5140` u16 / `sub_8F5160` u32 / `sub_8B3250` dstr)与客户端出站构包器(`sub_8B2650` begin / `sub_8B2450` append / `sub_8B24C0` flush)。
3. **业务函数与数据**:本功能用到的管理器单例、查找/创建/遍历函数,及记录内关键偏移(如用户表 `sub_4FDDB0/4FDF60/4FDDF0`,数据区指针 `sub_404300` + 各字段偏移)。
4. **客户端发送点**:每个相关 CMD 的发送函数/发送地址、发送前的客户端本地校验(错误文案 id 一并记录)。
5. **应答消费**:CMD 应答分发器内本功能的 case 地址、失败分支的读取形状与弹提示的错误码。

## 3. 地址与函数名书写规则

- 一律写 VA(ImageBase 0x400000),函数用 IDA 自动名 `sub_XXXXXX`;确证语义后可在登记表建议名,但文档正文保持 `sub_XXXXXX` 便于回溯。
- case 区间用 `起始..结束` 表示,结束地址 = 跳转表中下一个 case 入口(按表项地址排序推算);**注意**部分 case 物理上不相邻(如 NOTI 9 实际延伸到 0x41C2F0,中间被 NOTI 128 穿插),边界必须用 py_eval 扫 `idaapi.get_switch_info` 确认,不能按表序相邻推断。
- 立即数/偏移用 16 进制(如 `+0x1A`);字节序列用 `XX XX` 空格分隔。
- 字符串注明编码与来源(串表 id 经 `sub_8AA5A0` 还是 .rdata 裸串)。

## 4. 验证方式标注

每条结论标注取证方式,避免推断被当成实证:

- **反编译**(Hex-Rays 通过)/ **反汇编**(仅 disasm)/ **跳转表边界**(py_eval 扫 switch)/ **实测抓包**。
- 凡只有单一路径证据的(如仅静态无实测),在格式表上方统一声明,不逐条重复。

## 6. 线上格式结论的强制核对项(2026-09-30 sub_8B3250 事件教训登记)

背景:NOTI 9 设置段曾被结论为「只读 kind+userMax 两字节、队名文本不下行」,据此设计了 type 4 扩展块与客户端补丁;真机四轮不可用后,最终反汇编 `sub_8B3250` 才发现 kind==0 分支**无条件消费 u32 长度并按长度读文本**(原生即承载队名下行)。误读存续期间,函数寄存册与本规范 §2 均已登记 `sub_8B3250` 为 dstr 原语。以下六条为强制核对项:

1. **原语必须读到叶子**:声明任何「该字段不下行/读取端只读 N 字节」结论前,必须把该读取路径上被调的原语函数反汇编到本体(含其在长度异常分支的行为),不得按调用点实参形态(如"传了串指针+长度像 strncpy")推断语义。
2. **登记册冲突必须先调和**:调用点表象与本规范 §2/函数寄存册已登记的原语分类不一致时,先反汇编核实再下结论,禁止解释性带过。
3. **上/下行默认对称**:同一设置项的上行与下行形态默认同构;两者不同时,该【差异】标记本身即待验证项,须给出读取端反汇编级证据后才能保留。
4. **静默无效果优先查游标**:本协议族游标为全局、无边界防护、分发器不做消费校验,"发包被接受但界面无任何变化"是游标错位的典型签名,游标位置/后续字节转储应列为首轮诊断手段,先于部署环境排查。
5. **承接结论须重验**:前一轮文档结论被用作新设计(扩展/补丁)前提时,该前提与新增部分同属评审对象;验证过的新增细节(如"未知类型被跳过")不能替代对前提的验证。
6. **字节级闭环才算定谳**:服务端写出字节与客户端读取路径逐字节对账(两端都能说出同一偏移上是什么)之前,任何根因结论只视为工作假设。
