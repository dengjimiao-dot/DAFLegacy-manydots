# Ijl15 客户端补丁:任务触发器写入后重建任务窗(已作废)

- 状态:**已作废**(实装后真机复现选角→进房转换期 UI 损坏,已整体回退;本文留档机制结论与失败原因)
- 关联:`PENDING.md` P-51、`docs/protocol/packet-detail-skill-quest-60cn.md`(CMD 33–36 格式)

## 1. 背景与目标(历史)

60CN 客户端的任务窗(左侧详情 + 右侧列表)内容在重建时一次性构建,重建点仅存在于 LOGIN/SELECT_CHARACTER 应答、NOTI 27(START_GAME)、窗口重开与场景切换(详见 P-51 的 IDA 复核)。CMD 35 应答经 `sub_4EBB60` 写入触发器存储并置任务记录完成标志,但**不触发任务窗重建**——已打开的任务窗不随"收集任务完成/回退"实时刷新。

服务端侧已补齐邮件提取/寄出后的触发器推送(P-51),使存储即时同步。本补丁曾尝试在客户端补上"触发器写入后强制重建任务窗",实装后造成选角→进房转换期 UI 损坏,已回退。

## 2. 客户端机制(IDA 锚点,结论仍然有效)

| 锚点 | 地址 | 语义 |
|---|---|---|
| 触发器存储例程 | `sub_4EBB60` | `__thiscall(questMgr, questId, trigger)`;写入混淆 trigger 存储,trigger=0 时置任务记录 +0x17C 完成标志、发系统消息(串 463)、恢复隐藏 NPC;返回任务记录指针(未命中返回 0) |
| CMD 35 应答调用点 | `0x4137F8`(case 35 @ `0x4137B3`) | `push trigger; push questId; mov ecx, ds:dword_B5DD00; call sub_4EBB60` |
| CMD 36 应答调用点 | `0x4138EA`(case 36 @ `0x4138B8`) | 同形,trigger 传 -1(任务完成移除) |
| 任务 UI 重建例程 | `sub_42FC10` | `__thiscall(core, mode)`;经 `sub_42F110 → sub_89DF90 → sub_79CE00` 重建任务窗,`sub_79CE00` 读混淆 trigger 存储(19 处) |
| 游戏主对象指针 | `dword_B5D6F0` | 重建例程的 this |
| 任务窗内容预构建 | `sub_79CE00` | 任务窗全部条目/页面一次构建;InfoWindow 虚表方法与页面构建器(`0x7F5A60`/`0x7F5BD0`/`0x7F5D50`/`0x7F60F0` 状态分发)均**不**读取触发器存储与 +0x17C 标志 |

## 3. 已试方案与失败原因

**方案**:把 `sub_4EBB60` 的两处调用点重写为包装例程——原例程存储成功(返回非 0)后调用 `sub_42FC10(core, 0)`,使任务窗实时刷新。

**失败现象**(2026-10-11 真机):选择角色后未进入赛利亚房间,角色列表变为全空——重建在错误的游戏阶段被执行。

**根因**:原生的 `sub_42FC10` 调用点全部带**游戏状态守卫**(LOGIN 应答 case 1 要求 `sub_402030(this+4) == 5`;SELECT_CHARACTER 应答 case 4 要求 `sub_857580(30) == 1`)。触发器存储例程在选角→进房的加载转换期同样会被 CMD 35 应答命中(客户端在拿到选角应答里的任务槽与背包后即本地评估并发 CMD 35),包装例程无守卫,重建链在该阶段踩到未就绪的界面状态。

**教训**:在此客户端上挂钩任务 UI 重建,必须携带与原生调用点等价的状态守卫;更保守的层(列表选中回调)未定位,且任务窗内容为一次性预构建,「点击右侧条目时刷新左侧」原生并不存在,实现它需要新的钩子点与同等强度的守卫,收益(省一次窗口重开)与风险不成比例。

## 4. 现行方案

仅保留服务端侧修复(P-51):邮件提取/寄出后立即重算并推送 CMD 35 应答,触发器存储与完成标志即时同步;客户端按原版时机(重开任务窗、重选条目、重登、进城)呈现正确状态。原版客户端的呈现时机与本服一致,不构成与真服的行为差异。
